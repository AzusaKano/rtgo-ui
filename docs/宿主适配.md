# RTGo_slate 宿主适配规范（M1 · T15 通道换件的总账）

> 资产包只背样式；每个宿主自带一份「通道适配」，记录母本（微信小程序）用了哪些平台机制、
> 在别的宿主上由谁接走。新增宿主 = 复制下表加一列，值与类名零改动。

## 通道总表（母本机制 → 各宿主）

| # | 通道 | 母本（微信小程序） | Web 浏览器 | 其他宿主接入时 |
|---|---|---|---|---|
| T15-01 | 页根选择器 | `page{}` | `body{}`（已随资产落地） | Flutter→ThemeData；WinUI→应用资源字典 |
| T15-02 | 按压挂类 | `hover-class`（框架挂摘，start/stay=1ms） | pointerdown/up 挂摘同名类（gallery.js 可抄）或 `:active`；禁 ripple | 各自手势层挂摘 `.press/.press-scale/.press-flat` |
| T15-03 | 单位 | `rpx`（375 设计宽） | `px`（52rpx→26px，资产已换；哨兵 U-5a 看守母本） | 换算后写死或自建比例通道 |
| T15-04 | 字号缩放 | `<page-meta root-font-size="system">` 喂 rem | 宿主调 `html{font-size}`（默认档=基准 px 已保证） | 读系统字号档设置映射 |

## Web 宿主胶水清单（资产包**不背**的浏览器机制）

资产包只管「组件长什么样」。把组件放进浏览器页面还差一层胶水，补的是浏览器默认行为
（UA 样式、文档体、滚动容器），不是设计值。这层必须由宿主提供，资产包故意不写：
写进去会与宿主既有的 reset 打架。

> 出处：2026-11-02 Web 端实测整理。缺这层的表现是「看着像没生效」，而不只是样式不好看。

| # | 要补什么 | 为什么 | 最小写法 |
|---|---|---|---|
| 1 | 文档体内距与字体 | 资产包的 `body{}` 只给令牌和底色，**不带 margin 与 font-family**；不补就会看到四周 8px 白边、正文用 Times | `html,body{margin:0;height:100%}` + `body{font-family:-apple-system,BlinkMacSystemFont,"PingFang SC","Microsoft YaHei",sans-serif;-webkit-font-smoothing:antialiased}` |
| 2 | 表单控件重置 | 资产只重置了 `button`，**没有 `input`**；UA 会给输入框加边框、背景、内距，把定高与内距全顶开 | `input,textarea{border:0;background:transparent;outline:none;padding:0;font-family:inherit}` |
| 3 | 滚动容器替身 | 母本的 `scroll-view` 是原生滚动容器；`.screen-scroll` / 站选器列表在 Web 上要有 `overflow` 才滚得动 | `.screen-scroll,.station-picker-list{overflow-y:auto;-webkit-overflow-scrolling:touch;overscroll-behavior:contain}` |
| 4 | 键盘可达性 | 资产包不写 `:focus-visible`（那是宿主的设计决定），但完全不给焦点环 = 键盘用户看不见自己在哪 | `:focus-visible{outline:2px solid var(--brand);outline-offset:2px}` |
| 5 | 顶栏第三个子项 | 见 T03-02c：加 `.topbar-main` + `.topbar-actions`；母本的 `:last-child{flex:1 1 auto}` 会误拉伸动作钮 | 两个类都给，顺序由资产包保证 |
| 6 | 固定顶栏让位 | `.ios-fixed-topbar` 是 `position:fixed`，正文要让出 72px（+ 页面内距 14） | 内容容器 `padding-top:86px` |

**不要做**：不要为「看起来居中」改资产包数值；不要给按钮加 ripple（母本没有）；
不要自己写 `min-width` 去救被挤窄的按钮，先查是否漏了上表第 2 条。

## 宿主职责边界（接什么线）

资产包交付后，宿主只做三件事（页面级断言只查这些）：

1. **状态**：选中态类（`.active/.is-open/.is-selected…`）由宿主状态机挂摘；
2. **按压**：按 T15-02 挂摘按压档类（基态 transition 已在资产内，宿主不要叠加 transition）；
3. **导航/取数/原生组件**：路由、数据、map/转轮吸附等平台件。

宿主接入后建议跑一次「资产类零引用 = 孤儿」检查：把 `gallery.html` 里出现过的类名与
工程里实际用到的类名各列一遍，差集就是写好了没接线的件（gallery 的接线段即此模式）。

## 消费方式

```html
<!-- 方式 A（推荐）：只入令牌 + 按需入组件层 -->
<link rel="stylesheet" href="rtgo-tokens.css">
<link rel="stylesheet" href="rtgo-components.css">

<!-- 方式 B：入拼合 bundle（含纪律头注释，体积略大） -->
<link rel="stylesheet" href="rtgo-slate.css">

<!-- 可选：要「浅色/深色/跟随系统」三选一，再加这一份 -->
<link rel="stylesheet" href="theme-overrides.css">
```

**主题三选一怎么接**（`theme-overrides.css` 是 `构建脚本` 的产物，值为令牌层逐字拷贝）：

| 用户选了什么 | 怎么挂 |
|---|---|
| 跟随系统 | `<body>` **不加类**（回落 `rtgo-slate.css` 里的 `@media (prefers-color-scheme: dark)`） |
| 强制浅色 | `<body class="theme-light">` |
| 强制深色 | `<body class="theme-dark">` |

只挂类、不改值。⚠ 不要用 JS 读 CSS 文本再拼 `<style>` 覆盖作用域：正则会吃掉
`background:` / `color:` 这类以字母开头的声明（被当成选择器），结果是切了深色但底色没变。
该文件的价值在于把这件事做在构建期，用花括号配对解析。

- 改观感只许覆盖令牌（`--brand`、`--card`…），不许改组件声明（A 类件改值 = 开例外，先改令牌）；
- 拼合产物与主题档都是生成的：**不要手改**，改源文件后重新生成。

## Flutter 宿主专页（v1.6 · 资产包 = rtgo-flutter（原 slate-ui-kit，2026-11-01 更名），对账见 Flutter 对账脚本）

### 字重 snap 换算表（跨范式移植必读 · 源：slate_tokens.dart 注释，2026-10-31 回流）

母本大量使用非整百字重（750×29、850×10、650×6、450×1），但 Flutter 的 `FontWeight` 只有
100~900 九个整百常量，`FontWeight.lerp(w700, w800, .5)` 也会 round 回 w800，无法表达 750。
唯一能落 750 的是可变字体 + `FontVariation('wght', 750)`，但 kit 不声明 fontFamily（与母本一样
回落系统字体），走不了这条路。

**母本同样是 snap 的**：微信 WebView 的 CSS 字重也要匹配系统字体实际提供的档位
（PingFang / Noto 只有 400/500/600/700 等），规则为 >500 向上取最近、≤500 向下取最近：

| 母本值 | 出现次数 | snap 结果 |
|---|---|---|
| 450 | ×1 | **w400** |
| 650 | ×6 | **w700** |
| 750 | ×29 | **w700** |
| 850 | ×10 | **w800** |

因此跨范式移植直接写 snap 值不是妥协，而是还原：母本在真机上的实际渲染就是 snap 结果。
需要修正的只有「原值比 snap 结果低一档以上」的那几处（micro11 / tag10 / body14Regular /
strong18；slate-ui-kit 的 getter 已修，依据见其源注释：母本 11px 字重都在 700~800）。

### 范式转换雷区清单（16 条事实 · 2026-10-31 吸收 · 源：轨交 Flutter 工程 docs/迁移雷点.md）

> 定性：范式差异事实，即「小程序里天然正确、Flutter 里默认就错」或「两环境机制不同、照搬就错」；
> 不属于流程方法，事实不随纪律演进过时。全部由实机对比暴露，条条带实例与量测口径。
> 2026-10-31 定稿：作为事实吸收本页（原判「方法不回流」，通读后确认 11 条为纪律未覆盖的
> 范式专属事实）。Flutter 移植轮次开工时本清单为必引文献。

#### ★ 移植必读（Flutter 范式专属事实，11 条）

1. **文本符号箭头/叉/三角一律不搬**（回退链不同）：母本 `→` `×` `‹` `▾` `⇄` 是文本字符，
   WeChat Android 无 Arial 回退系统字体，Flutter 走 Roboto→设备 CJK 另一条回退链：`→` 挂低、
   `⇄` 从 14.8×14.8 掉到 10×8.6 且偏下 2.2dp。对策逐个判断，不一刀切：`⇄`/`▾` 位置敏感 → 自绘
   （SlateGlyphKind.swap/caretDown）；`→` 定稿为回退系统字形（自绘风格与设备字体不一致，
   宁可接受回退偏移）。⚠ 不要用 GDI+ 默认回退来验证 Flutter 的绘制结果：私字体缺字也会静默
   回退，量出来的不是 Roboto。
2. **CSS 行内基线排版 ≠ Flutter baseline**：一行里 16px 主值 + 13px 后缀 + 12px 图标共用基线是
   浏览器天然行为；Flutter `Row(baseline)` 里无真实基线的子项（图标 / 图形盒）为顶端对齐，
   `Baseline` 包装无效（RenderBaseline 对无基线子项返回 null）。对策：图形盒自己实现
   `computeDistanceToActualBaseline`（盒底=基线）；并补 `computeDryBaseline`，否则
   IntrinsicHeight/WidgetSpan 场景直接抛异常。文字混排用 `Row(baseline)` 或 `Text.rich`。
3. **`→` 类字符量测基准** = 「母本字体在目标字号的墨迹」，不是 Flutter 字体（GDI+ 量 Arial：
   → 宽 0.9225em、中心在基线上 0.2525em）。
4. **CSS border 画在盒内、Flutter Container 带 border 会撑盒**：42 内容 + 1px 边 = 44×44，
   `borderRadius:21` 不再是圆（实例：YmCircleButton 变椭圆）。对策：外层 SizedBox 硬约束尺寸，
   或 border 画进 Pressable 的 decoration（盒底=尺寸）。
5. **按压反馈层序**：hover-class 改的是元素自身的背景；Flutter 若按压色画在一层容器、child
   又垫不透明底，tint 永远看不见，且不报错（实例：SlateRouteCard 无按压反馈）。对策：装饰挂
   Pressable 自己的 decoration，child 透明。同时核对档位：press = 换底加缩放，不是只换底的 flat。
6. **CSS transition 只过渡 transform 时底色是瞬切的**：Flutter `AnimatedContainer` 会给底色
   也加 250ms 渐变，每次按压都比母本软（实例：YmPressable 底色改瞬切）。
7. **固定尺寸要显式给**：CSS `width:42px;height:42px` 不会丢；Flutter 少套一层约束就被内容或
   父级撑变形（实例：44×44 圆钮、Column 默认 mainAxisSize.max 把字段撑满全屏）。
9. **字号继承链不同**：小程序「不设字号」= 继承 16px 页面基准；Flutter TextStyle 无级联，
   每个 Text 都要显式给对字号（实例：站台号 .sub/.meta 都是 12px，Flutter 写成 13/12 两号）。
12. **状态色档位对母本全量核对**：母本没有的档（如末班车横幅「品牌色淡底」）属迁移时自行发明，
    应以 `wx:else` 默认底（--warn 橙）为准；同时核对同色系投影（status 投影 0 8 24 .24）。
13. **Colors.transparent 是「透明黑」**：与 Color.lerp 组合中途会经过半透明灰，静止底色要用
    「同色 0 alpha」起点（实例：YmPressable 注释）。
14. **量测先用探针、再上实机**：widget golden（1x）+ 像素扫描脚本能把「偏高 1.5dp」「墨迹 12.8 vs
    17」量化成数字；测试字体（FlutterTest/Ahem）字形是方块，只可量排版不可比字形，量字形要
    FontLoader 加载真字体（Roboto + 一个 CJK 近似）。

#### ⊕ 已被现行纪律覆盖（同构对照，无需另行看守）

8. **min-height 类约束是「下限」**：先定「设计基准是哪个数」再全站统一，照抄某一页的常量就会
   分叉（实例：顶栏 62 特例 vs 72，与 T03-02 的 72 定稿同口径）。
10. **同名 class 多处定义时生效的是后一个**（.line-pill 两处定义后者覆盖）→ RTGo 对账器逐值
    对账天然看守。
11. **hover-class 挂在哪个节点，按压就发生在哪个盒**（整卡/胶囊/只换底）→ T13 按档拆分粒度。
15. **改「全库唯一入口」先 grep 全部用法**（一个参数增删同时作用于圆钮/卡片/胶囊/列表行）→
    基态组/令牌层纪律。
16. **母本源码是唯一事实**（后定义覆盖先定义、页面常量、@import 继承都要回源对账，不能凭
    迁移后代码里的旧注释）→ 真值源声明 + 断言现查。
